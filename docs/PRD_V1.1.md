# 家庭自用营养师 App 产品需求文档

> 文档版本：V1.1（开发依据版）  
> 整理日期：2026-11-12  
> 产品暂称：家庭自用营养师 App  
> 当前阶段：产品需求与页面方向已确认，尚未开始编码  
> 文档效力：取代此前分散讨论及《家庭自用营养师 App 产品需求说明书》V1.0  
> 配套规范：《营养师数据 Markdown（NDM）格式规范》1.0

## 1. 产品背景与定位

本产品希望让营养师以更自然、更有陪伴感的方式进入日常生活。它不仅计算热量，还要结合用户当次已有的食材、个人目标、口味、运动、用餐历史和健康指标，给出具体、可执行、能够长期坚持的饮食建议。

产品仅供个人及家庭自用，第一版为单用户应用，不考虑多人档案、家庭共享、社交排名或公开平台运营。

产品的核心体验是：

> 打开 App，用户能马上知道“这一餐可以怎么吃”；完成记录后，能逐渐理解“为什么这样吃”；即使偶尔偏离计划，也愿意继续回来。

## 3. 产品目标

1. 回答“现在这些食材，早餐、午餐、晚餐具体怎么吃更健康”。
2. 给出具体菜品、用量、做法和营养估算，而不只是抽象建议。
3. 让用户逐渐理解配菜理由，形成基础营养知识。
4. 根据运动计划和实际完成情况动态调整后续饮食。
5. 长期记录饮食、运动和健康指标，呈现坚持成果。
6. 尊重口味和偶尔想吃计划外食物的需求，避免羞辱式管理。
7. 为高血压、糖尿病、肾病等情况提供饮食辅助和食补知识，但不替代诊疗。
8. 保证数据可保存、可导出、可导入、可迁移。
9. 通过简洁界面、悬浮角色和勋章体系降低长期使用的心理负担。

## 4. 核心设计原则

### 4.1 当次食材与额外推荐严格分离

- **当次已有食材**：由当次照片识别并经用户确认，可以参与本次配菜。
- **额外推荐食材**：仅用于弥补营养结构不足，不参与本次菜谱，不计入本次营养估算。
- 用户确认实际食用后，相关食材和菜品才进入用餐记录。
- 不建立、不展示、不维护任何形式的食材库存。

### 4.2 建议优先级

配餐时按以下顺序处理约束：

1. 食物过敏、明确忌口及疾病饮食限制。
2. 当次实际已有且确认可用的食材。
3. 增肌、减脂或维持健康等个人目标。
4. 三餐之间的营养结构与合理分配。
5. 运动计划和实际运动完成情况。
6. 辣、甜等口味偏好及菜品多样性。

口味偏好应尽量满足，但不能凌驾于明确的健康限制之上。

### 4.3 陪伴而非惩罚

- 偶尔吃肯德基、奶茶或其他计划外食物，不清零长期成果。
- 不鼓励极端节食、催吐或过度运动补偿。
- 如实说明食物影响，帮助用户回到正常饮食节奏。
- 漏记只表示没有记录，不据此判定用户没有坚持健康饮食。

### 4.4 简洁而非简陋

- 首页只突出一个主要行动：拍照配餐。
- 复杂数据进入记录详情，不全部堆在首屏。
- 核心任务进入专注模式，一次只处理一个步骤。
- 悬浮角色负责解释与陪伴，不遮挡主要操作。
- 视觉参考“不背单词”的低干扰、强主线、留白和完成感，但不照搬其学习页面。

## 5. 信息架构与页面结构

### 5.1 主导航

第一版仅保留三个主入口：

| 主入口 | 核心任务 |
| --- | --- |
| 今天 | 安排下一餐、查看今日进度、获取知识和情境提醒 |
| 记录 | 查看日历、历史记录、营养趋势、运动、健康指标和坚持成果 |
| 我的 | 管理档案、忌口、餐具、授权、勋章、数据与设置 |

手机使用底部导航；Y900 平板使用左侧导航栏。

### 5.2 首页“今天”

内容顺序如下：

1. 日期、当前饮食目标和轻量坚持信息。
2. 下一餐卡片，例如“午餐还没安排”。
3. 全页最醒目的主按钮“拍照配餐”。
4. 早餐、午餐、晚餐的完成状态。
5. “营养师说”知识气泡。
6. 与今天有关的运动、健康或勋章进度提醒。

首页要求：

- 下一餐和拍照配餐是视觉主角。
- 不再固定摆放大尺寸角色，角色通过悬浮球出现。
- 首页只展示一个即将达成的勋章进度，避免勋章墙占据首屏。
- 知识在首页直接可见，但保持简短。
- 历史图表和详细健康数据进入“记录”。

### 5.3 “记录”页面

包含：

- 日历视图。
- 累计记录天数、累计坚持日、当前连续记录和历史最长记录。
- 饮食、运动、健康指标分类切换。
- 营养供能比例及趋势图。
- 历史用餐列表和单次详情。
- 运动计划与实际完成对照。
- 健康指标历史趋势。
- 勋章入口及阶段成果。

### 5.4 “我的”页面

包含：

- 个人档案与饮食目标。
- 过敏、忌口、口味和疾病情况。
- 医生或临床营养师饮食限制。
- 餐具校准。
- vivo 健康授权。
- 知识册、角色与勋章。
- NDM 导入、导出和备份。
- 隐私、AI、通知、悬浮球和显示设置。

### 5.5 二级及专注页面

| 页面或流程 | 类型 | 说明 |
| --- | --- | --- |
| 首次使用引导 | 专注流程 | 创建档案、目标、忌口、疾病信息及必要授权 |
| 拍照配餐 | 专注流程 | 指引、拍摄、确认食材、生成菜谱 |
| 配餐结果 | 非专注页面 | 显示菜谱、营养和额外推荐，角色可解释 |
| 菜谱烹饪步骤 | 专注页面 | 隐藏悬浮球，减少干扰 |
| 实际用餐确认 | 专注流程 | 确认菜品、食用量和计划外状态 |
| 运动计划与详情 | 普通或专注 | 查看时可有角色，连续填写时隐藏 |
| 健康指标录入 | 专注页面 | 避免遮挡数值、单位和保存按钮 |
| 知识详情与知识册 | 非专注页面 | 支持角色解释、收藏和回看 |
| 勋章墙与奖励 | 非专注页面 | 展示进度、点亮记录和角色寄语 |
| 餐具校准 | 专注流程 | 隐藏悬浮球 |
| NDM 导入预览与冲突处理 | 专注流程 | 隐藏悬浮球，避免误操作 |

## 6. 整体视觉与交互风格

### 6.1 设计关键词

**温和、干净、生活感、低干扰、专业但不冰冷。**

- 使用充分留白和明确层级。
- 卡片采用圆角、细边框和极轻阴影。
- 食物图片和简单插画是生活感的主要来源。
- 不使用复杂壁纸降低文字和图表可读性。
- 不做医疗仪表盘式首页。
- 不用红色失败标记、批评文案或焦虑式连续签到提醒。

### 6.2 基础色彩建议

| 用途 | 建议颜色 |
| --- | --- |
| 页面背景 | 暖白 `#FAFAF7` |
| 主色 | 鼠尾草绿 `#708B74` |
| 主要文字 | 深灰 `#292D2A` |
| 次要文字 | 中灰 `#7A807B` |
| 奖励点缀 | 柔橙 `#E7A56F` |
| 分割线 | 浅灰绿 `#E4E8E2` |

营养图表需使用容易区分的颜色，并同时提供文字和数值，不只依赖颜色表达结果。

### 6.3 字体、图标与动效

- 优先使用系统无衬线字体。
- 标题、正文、辅助文字和数字应有稳定层级。
- 数字对齐，图表单位清晰。
- 图标以简洁线性图标为主。
- 动效只用于页面反馈、角色表情和勋章点亮。
- 普通勋章动画控制在一两秒，不强制全屏，不阻断操作。
- 支持系统字体放大和减少动态效果等基础无障碍需求。

### 6.4 文案语气

推荐：

- “这一餐已经不错，下次可以多一份蔬菜。”
- “这一餐已经记下来了，之前的坚持仍然算数。”
- “今天没有记录，不代表你没有好好吃饭。”

避免：

- “不合格。”
- “你又破戒了。”
- “坚持失败。”
- “必须运动消耗掉这一餐。”

## 7. 功能需求

### 功能一：根据当次食材安排三餐

#### 用户输入

- 将不同食材分开放置，加入固定参照物后拍照。
- AI 识别食材并估算用量。
- 用户确认或修改识别结果。
- 用户选择安排某一餐，或一次安排全天三餐。

#### 系统输出

- 具体菜品名称。
- 每种食材的用量及对应份数。
- 简明制作步骤。
- 能量和主要营养素估算。
- 配菜理由及与目标的关系。
- 如有必要，单独列出建议以后补充的食材。

#### 关键规则

- “现在就能做”的菜谱只能使用当次已有食材和用户确认的常备调味品。
- 额外推荐食材必须单独展示，不得混入菜谱或营养计算。
- 食材条件不足时，应明确说明限制，不编造食材，也不强行生成所谓完美食谱。
- 生成菜谱不代表已经食用；实际用餐由用户另行确认。
- 不跨餐次虚构库存，也不进行库存扣减。

### 功能二：首页知识与长期知识积累

知识内容以“人物说话”为主要形式，不做复杂课程或资讯流。

#### 三层知识结构

1. **气泡重点**：用几句话说明一个知识点。
2. **为什么**：展开通俗解释、与当前情境的关系和适用边界。
3. **知识册**：收藏、回看和查看已读内容。

#### 内容范围

- 食材特点和常见营养误区。
- 饮食习惯、食疗和食补知识。
- 配菜理由。
- 运动与饮食。
- 疾病饮食辅助。
- 健康指标的基础解释。

#### 展示规则

- 每天首次打开首页时，可主动出现一条今日知识。
- 配餐、用餐、运动和健康页面中的知识应与当前情境有关。
- 同一条内容不反复弹出。
- 用户可选择“今天不再提示”。
- 疾病相关内容不宣传某种食物能够治愈疾病或替代药物。
- 重要知识宜保留可靠来源和审核日期。

### 功能三：运动建议与动态配餐

#### 两种运动状态

1. **计划运动**：例如“下午准备跑 20 分钟”，用于制定预案。
2. **实际运动**：根据实际项目、时长、强度和完成情况调整后续饮食。

#### 动态调整规则

- 计划运动不得直接记为已消耗。
- 用户取消、缩短或改变运动时，应更新相应饮食建议。
- 结合个人目标、全天饮食、运动强度和健康情况决定是否调整。
- “跑 20 分钟后晚餐补充蛋白质”可以作为调整方向，但不是机械规则。
- 可推荐运动项目、强度、时长和注意事项，但不忽视疾病或身体不适提示。
- 保存计划、实际执行和配餐调整之间的关联，形成长期记忆。

### 功能四：用餐记录与坚持统计

#### 每次用餐记录

- 日期、时间和餐次。
- 具体菜品、食材和用量。
- 实际食用量及估算方式。
- 碳水化合物、蛋白质和脂肪的克数。
- 三大营养素的供能比例扇形图。
- 能量及后续确定的其他营养指标。
- 本次饮食评价和简明改进建议。
- 是否为计划外饮食及相关备注。

#### 统计内容

- 累计记录天数。
- 累计坚持日。
- 当前连续记录和历史最长连续记录。
- 本周或本月合理用餐比例。
- 运动记录和阶段目标完成情况。
- 勋章进度及历史成果。

扇形图默认展示三大营养素的**供能比例**，同时显示克数，避免把不同营养素的重量直接误当作能量比例。

### 功能五：个人档案与个性化目标

首次打开 App 时建立单用户档案，之后可随时修改。

#### 基本资料

- 昵称、年龄或出生日期、生理性别等必要资料。
- 身高、体重及其历史变化。
- 日常活动水平。

#### 饮食目标

- 增肌。
- 减脂。
- 维持健康。
- 后续可扩展其他目标。

#### 饮食约束和偏好

- 食物过敏。
- 明确忌口和不吃的食材。
- 辣、甜、酸等口味偏好。
- 高血压、糖尿病、肾病等已填写健康情况。
- 用户主动补充的医生或临床营养师饮食限制。

用户填写疾病情况后，App 根据相应饮食原则调整当次食谱。补充更多身体指标和医生限制后，进一步精细调整。资料不足时仍可生成基础健康食谱，同时提示哪些判断无法精确完成。

### 功能六：食材用量估算与餐具校准

#### 拍照规范

- 不同食材分开放置，尽量避免遮挡。
- 固定参照物与食材尽量处于同一平面。
- 建议镜头尽量垂直拍摄。
- 对堆叠、透明、混合或形状不规则食材提示误差风险。

#### 估算流程

1. 识别食材。
2. 根据参照物、餐具校准及食材特性估算用量。
3. 显示估算值或合理区间及可信程度。
4. 用户确认或修改。
5. 将确认值用于配餐和记录。

#### 餐具校准

- 通过一碗水、一勺水等操作估算日常餐具容量。
- 保存不同碗、勺的名称、容量、校准日期和说明。
- 水的校准结果主要用于理解容量，不能默认直接等同于盐、油、米等食材重量。
- “一勺盐”等常用量可单独校准。
- 支持手动输入厨房秤称重结果，作为提高准确度的补充方式。
- 区分生重、熟重和可食部，避免记录口径混乱。

### 功能七：健康指标分析与 vivo 健康接入

#### 数据来源

- 手动录入血压、血糖、血脂等数据。
- NDM 文件导入已有记录。
- 后续可通过照片辅助识别化验单，但必须由用户确认数值、单位和参考范围。
- 预留 vivo Health Kit 官方授权接入。

#### 分析与提示

- 展示历史趋势和变化。
- 结合测量时间、单位和数据来源进行解释。
- 提供日常饮食和生活方式建议。
- 对明显异常或持续异常给出及时就医提醒。
- 不自动诊断，不建议自行停药、换药或调整药物剂量。
- 不默认运动手表能够提供完整血糖、血脂等数据。

#### vivo 健康接入策略

- 预留官方 Health Kit 接入能力。
- 手动录入和文件导入始终可用。
- 未获得接口权限时不影响其他功能。
- 获得权限后，只同步用户明确授权且平台支持的数据。
- 官方接入资格、审核要求和实际可读数据类型需在实施前验证。

官方说明：[vivo 健康服务平台简介](https://developers.vivo.com/doc/d/bb71c60ceaf645b7af51a4365a5676bb)

### 功能八：计划外饮食的人性化处理

当用户突然想吃肯德基套餐等计划外食物时，提供以下选择：

- 按原计划吃。
- 少量或调整搭配后食用。
- 偶尔正常食用，不作补偿性惩罚。

系统应当：

- 如实说明该食物与当前目标的差异。
- 给出份量、搭配和当天其他餐的温和调整建议。
- 在用户确认后正常记录，不把食物虚构成健康食品。
- 保留长期坚持成果，不因一餐自动清零。
- 对医生明确限制的食物显示更醒目的提醒。
- 允许用户通过悬浮角色表达“我想吃点别的”，但不把角色聊天作为唯一记录入口。

### 功能九：二次元悬浮角色、勋章与奖励

第一版采用：

- 可爱、甜美的二次元营养师形象。
- App 内可拖动悬浮球。
- 多张表情立绘。
- 有统一性格的文字对话。
- 勋章、阶段奖励和坚持激励。
- 动态 Live2D 和语音留待后续版本。

悬浮球、知识和勋章的详细规则见第 8、9 章。

### 功能十：本地保存、NDM 导出与导入

- 日常使用数据保存在本地数据库中，关机和重启后不得丢失。
- 支持导出本软件专用的营养师数据 Markdown，后缀为 `.ndm.md`。
- 支持完整备份包，保存 NDM 文档、照片和附件清单。
- 照片不直接嵌入 Markdown 正文，通过相对路径与记录关联。
- 导入前先预览、校验并备份现有数据。
- 相同记录不得重复导入。
- 冲突记录由用户确认，不直接覆盖。
- 每条记录保留唯一编号、来源设备、创建时间和修改时间。
- 不支持也不要求导入任意普通 Markdown 笔记。
- 第一版不设计 Excel 导入导出。

## 8. 二次元悬浮角色规范

### 8.1 定位

悬浮球代表“营养师本人”，是贯穿 App 的解释与陪伴入口，不是纯装饰，也不是替代核心功能的聊天机器人。

### 8.2 显示范围

悬浮球存在于 App 内各个非专注页面，包括：

- 首页。
- 配餐结果。
- 记录及记录详情。
- 知识详情和知识册。
- 勋章墙。
- 我的及普通设置页面。

以下专注页面隐藏：

- 拍照及食材确认。
- 餐具校准。
- 菜谱烹饪步骤模式。
- 健康数据手动填写。
- NDM 导入预览和冲突处理。
- 其他需要连续输入或防误触的页面。

悬浮球仅在 App 内工作，不申请系统级跨应用悬浮窗权限。

### 8.3 基础交互

- 默认只显示大小适中的角色头像。
- 支持拖动，松手后吸附到屏幕边缘。
- 自动避开底部或侧边导航、主要按钮和系统手势区域。
- 点击展开对话气泡，点击空白处收起。
- 键盘弹出时自动避让或暂时收起。
- 手机和平板分别调整尺寸及安全区域。
- 用户可在设置中关闭悬浮球。
- 关闭角色后，知识、配餐解释、勋章和计划外饮食记录仍有普通页面入口。

### 8.4 主动与被动触发

主动触发仅限：

- 每天首次打开首页的一条今日知识。
- 完成配餐或用餐记录后的相关解释。
- 点亮勋章或达到重要阶段。
- 必要的健康或操作提示。

其他时间保持安静，由用户主动点击。不得持续跳动、频繁弹话或反复催促。

### 8.5 不同页面的角色内容

| 页面 | 角色内容 |
| --- | --- |
| 首页 | 今日知识、轻量提醒 |
| 配餐结果 | 解释搭配理由和额外推荐 |
| 用餐记录 | 指出合理之处和下次微调方向 |
| 运动记录 | 解释运动与后续饮食的关系 |
| 健康趋势 | 解释趋势及必要时咨询专业人士 |
| 勋章页面 | 庆祝成果、提出适当奖励 |

## 9. 勋章与坚持体系

### 9.1 核心原则

勋章奖励长期做得到的事，而不是奖励每餐完美。

- 累计成果不因中断而熄灭。
- 连续记录只是辅助统计。
- 计划外饮食不清零长期成果。
- 不用勋章鼓励极端节食或过量运动。
- 中断后重新开始也是一种值得肯定的行为。

### 9.2 三类日期统计

| 类型 | 达成条件 | 用途 |
| --- | --- | --- |
| 记录日 | 当天至少确认一条真实用餐记录 | 奖励持续记录，不评价吃得好坏 |
| 坚持日 | 当天完成至少一项符合个人目标的行动 | 奖励长期健康习惯 |
| 均衡日 | 根据全天记录，整体大致符合个人目标 | 奖励整体饮食结构 |

计划外食物不妨碍获得记录日；是否影响坚持日或均衡日，应结合全天情况，而不是根据一餐直接判定。

### 9.3 勋章分组

#### 坚持系列

| 勋章 | 条件 |
| --- | --- |
| 第一束光 | 完成第一次真实用餐记录 |
| 三日新芽 | 累计 3 个坚持日 |
| 七日同桌 | 累计 7 个坚持日 |
| 十四日渐暖 | 累计 14 个坚持日 |
| 三十日烟火 | 累计 30 个坚持日 |
| 百日常青 | 累计 100 个坚持日 |
| 四季如一 | 累计 365 个坚持日 |

后续可增加 60、180 天等里程碑，但不改变累计不归零原则。

#### 餐桌系列

- 彩虹餐桌：达到配置化的蔬菜或食材多样性条件。
- 食材探索家：累计尝试并记录一定数量的新食材。
- 三餐有序：在用户设定的合理规则下保持稳定记录和用餐节奏。
- 搭配小能手：多次完成符合个人目标的当次食材搭配。

具体营养阈值应进入可维护的规则配置，不硬编码为所有用户相同的标准。

#### 运动系列

- 第一步：完成第一次真实运动记录。
- 说到做到：累计完成多次自己制定的运动计划。
- 动静有度：运动和休息安排较稳定。
- 轻松回归：中断后重新开始适量运动。

不设置“消耗越多越好”的勋章。

#### 知食系列

- 知食入门：读完规定数量的营养知识。
- 懂一点为什么：多次展开配菜或健康建议的解释。
- 我的知识册：收藏并回看一定数量的知识。
- 学以致用：知识关联的健康行为后来出现在真实记录中。

#### 从容系列

- 诚实记录：首次主动记录计划外饮食。
- 不必完美：计划外饮食后，下一餐正常回归并记录。
- 重新出发：中断一段时间后重新开始记录。
- 从容选择：在角色建议后，由用户自主作出并确认适合自己的选择。

### 9.4 连续记录与休息日

- 累计坚持日只增加，不归零。
- 当前连续记录与历史最长连续记录分开显示。
- 计划外饮食不打断连续记录。
- 漏记只影响连续记录，不否定实际饮食行为。
- 用户可将旅行、生病或不需要管理的日期标为休息日。
- 休息日不增加坚持日，也不打断连续记录。
- 不提供无限补签，避免形成额外操作负担。

### 9.5 首页与勋章墙

首页只显示一个轻量进度，例如“七日同桌：5/7”。

勋章墙采用搪瓷徽章风格：

- 未点亮：低饱和线稿，显示条件和进度。
- 已点亮：柔和彩色，展示点亮时间、达成依据和角色寄语。
- 图案使用小碗、勺子、新芽、星星和四季等元素。
- 手机双列，平板多列。
- 不做商城式货架或社交排行榜。

### 9.6 点亮和奖励

- 普通勋章：悬浮球表情变化、短气泡和一两秒轻动画。
- 30、100、365 天等重要里程碑：展示阶段庆祝卡和回顾。
- 用户可预设奖励，例如适量奶茶、看电影或买书。
- 奖励是可选建议，不强制执行。
- 存在疾病饮食限制时，不机械推荐不合适的食物奖励。

### 9.7 数据修正

- 勋章由真实用餐、运动、知识和计划记录自动计算。
- 补录和 NDM 导入的历史记录可参与计算。
- 保存勋章编号、当前进度、达成时间、点亮时间和关联记录。
- 修改误录后，未点亮进度静默更新。
- 已点亮的累计成果默认保留，不使用角色宣布收回等惩罚式反馈。
- 坚持统计快照只用于阅读，原始记录才是重算依据。

## 10. 核心使用流程

### 10.1 首次使用

1. 创建个人档案。
2. 选择饮食目标。
3. 填写过敏、忌口、口味和相关健康情况。
4. 说明本地存储与在线 AI 的使用边界。
5. 可选择校准常用碗勺。
6. 进入首页，查看下一餐和今日知识。

### 10.2 当次配餐

1. 选择餐次。
2. 进入专注模式，阅读拍摄指引。
3. 拍摄当次食材和固定参照物。
4. 确认识别出的食材及用量。
5. 系统生成只使用当次食材的菜谱。
6. 系统单独展示额外推荐食材。
7. 用户查看做法、营养估算和角色解释。
8. 实际用餐后确认记录。

### 10.3 运动联动

1. 用户添加运动计划。
2. 系统给出预备饮食建议。
3. 用户记录实际完成情况，或在获得授权后同步支持的数据。
4. 系统根据实际运动和当日饮食更新后续建议。
5. 保存调整原因，供以后回顾。

### 10.4 计划外饮食

1. 用户通过普通记录入口或悬浮角色表达想吃某种食物。
2. 角色以不批评的方式回应。
3. 系统说明影响并提供可选方案。
4. 用户自行决定。
5. 实际食用后正常记录，长期成果不因此清零。
6. 下一次正常用餐可触发“从容系列”正向反馈。

### 10.5 知识学习

1. 首页或当前情境出现角色气泡。
2. 用户阅读简短结论。
3. 可展开“为什么”。
4. 可收藏到知识册。
5. 系统记录已读、收藏和后续相关行为。
6. 同一条知识不反复主动弹出。

### 10.6 数据迁移

1. 在来源设备导出 NDM 或完整备份包。
2. 在目标设备选择导入。
3. 系统校验格式、版本、字段和附件。
4. 展示新增、重复、冲突、错误和缺失附件数量。
5. 用户确认冲突处理方式。
6. 系统先备份当前数据，再执行导入。
7. 展示导入结果摘要。

### 11.1 本地保存内容

- 个人档案和健康情况。
- 当次配餐、菜品、食材和营养记录。
- 实际用餐和计划外饮食记录。
- 计划与实际运动。
- 健康指标。
- 照片及附件关联。
- 餐具校准。
- 知识、已读和收藏。
- 角色必要互动上下文。
- 勋章、奖励和坚持统计。
- 应用设置及导入导出历史。

### 11.2 长期记忆原则

- 配餐时可读取本地历史，用于避免重复、理解偏好和结合运动。
- 运动计划必须和实际完成记录关联。
- 角色解释应能引用当前记录，但不虚构过去行为。
- 调用在线 AI 时，只提取当前任务所需的最少历史内容，不默认上传完整数据库。
- 用户修改或删除历史后，后续建议应使用最新数据。

### 11.3 主要业务实体

| 实体 | 作用 |

| 菜品与当次食材 | 保存菜品、用量、来源和照片关联 |
| 实际用餐 | 保存真实食用情况和计划外状态 |
| 营养快照 | 保存克数、能量和供能比例 |

| 健康指标 | 保存数值、单位、时间和来源 |
| 餐具校准 | 保存容量、方法和适用范围 |
| 知识与学习记录 | 保存内容、已读、收藏和关联行为 |
| 勋章与奖励 | 保存进度、达成、点亮和奖励 |

## 12. NDM 数据交换要求

NDM 全称为 Nutritionist Data Markdown，是本软件专用、标准 Markdown 可读的数据交换格式。

### 12.1 基本形式

- 文件后缀为 `.ndm.md`。
- 文档头使用 YAML Front Matter。
- 固定保存个人档案、配餐、用餐、运动、健康指标、餐具校准、知识与成就、附件清单等章节。
- 每条记录使用 HTML 注释标记类型和唯一编号。
- 菜品、食材和营养数据使用固定 Markdown 表格或记录块。
- 时间、单位、空值、枚举和附件路径使用统一规则。

### 12.2 食材来源约束

- `当次已有`且`用于配菜=是`：可以进入菜品和营养计算。
- `额外推荐`：只作建议，禁止计入本次菜品及营养合计。
- 不设置库存、剩余量或扣减字段。
- 估算值与用户确认值分别保存。

### 12.3 两种导出形式

- **轻量数据文档**：单个 `.ndm.md`，保存文字数据及附件状态。
- **完整备份包**：NDM 文档和 `assets` 附件目录，通过相对路径关联。

### 12.4 导入安全

- 校验格式标识和版本。
- 校验必填字段、编号、单位、枚举及食材来源关系。
- 校验附件路径和完整性。
- 完全重复记录默认跳过。
- 同编号不同内容进入冲突清单。
- 导入失败不得破坏原数据。
- 未知字段不得被静默丢弃后声称完整导入。

详细格式以《营养师数据 Markdown（NDM）格式规范》为准。

## 13. 在线 AI、隐私与权限

### 13.1 在线 AI

- App 内置接口，用户无需手工配置。
- 仅在主动使用拍照识别、智能配菜或相关知识功能时调用。
- 只发送完成当前功能所需的最少内容。
- 明确区分本地保存与在线处理。
- 接口密钥不得在公开资源或安装包中明文硬编码。
- 网络失败、接口超额或服务不可用时应明确提示，并保留手动操作路径。

### 13.2 权限原则

- 相机仅在拍照相关流程中申请。
- 健康数据读取必须单独授权。
- 不申请系统级跨应用悬浮窗权限。
- 非必要不读取通讯录、位置或无关文件。
- NDM 导入导出只访问用户选择的文件或应用专用目录。

### 13.3 健康内容边界

- 可以提供疾病饮食辅助、食疗食补知识和健康趋势提示。
- 不将建议表述为确诊、处方或药物调整。
- 不用单一指标给出确定诊断。
- 信息不足时说明不确定性。
- 明显异常或持续异常时提示及时就医。

## 14. 设备适配

### 14.1 vivo S7

- 使用底部三入口导航。
- 侧重快速拍照、配餐、用餐确认和随时查看。
- 保持单手操作路径简短。
- 悬浮球避开底部导航和主要按钮。
- 拍照识别失败时可快速手动修改。

### 14.2 联想拯救者 Y900 平板

- 使用左侧导航栏。
- 保留完整记录和编辑能力，不是只读客户端。
- 首页可采用双栏：下一餐与今日进度为主，知识和提醒为辅。
- 食材确认页左侧看照片，右侧修改食材与用量。
- 记录页左侧看历史列表，右侧看营养图和详情。
- 悬浮球根据大屏调整尺寸和吸附区域。

## 15. 第一版明确不包含

- 多人档案和家庭共享。

- 云账号和实时同步。
- Excel 导入导出。
- 任意普通 Markdown 笔记导入。
- 系统级跨应用悬浮球。
- Live2D 和语音角色。
- 社交、排行榜和公开分享。
- 医疗诊断、处方或药物调整。
- 对 vivo 健康接口一定审核通过的承诺。

## 16. 第一版验收要点

### 16.1 配餐与营养

- [ ] 首次启动可建立单用户档案并设置目标、忌口和口味。
- [ ] 每次配餐均可通过拍照形成当次食材清单，并由用户确认。
- [ ] 菜谱只使用当次已有食材和确认的常备调味品。
- [ ] 额外推荐食材不进入菜谱及本次营养计算。
- [ ] 不存在库存维护、剩余量管理或自动扣减功能。
- [ ] 可输出具体菜品、用量、做法、营养估算和理由。
- [ ] 可区分计划运动与实际运动，并据此调整建议。
- [ ] 可查看用餐历史、营养供能比例扇形图和坚持统计。

### 16.2 页面与角色

- [ ] 手机底部和平板侧边均只显示“今天、记录、我的”三个主入口。
- [ ] 首页突出下一餐和拍照配餐。
- [ ] 首页直接展示角色讲述的知识内容。
- [ ] 知识可展开解释并收藏到知识册。
- [ ] 悬浮球在非专注页面可拖动、吸附和展开气泡。
- [ ] 悬浮球在规定的专注页面自动隐藏。
- [ ] 悬浮球不遮挡主要按钮，键盘弹出时可避让。
- [ ] 关闭悬浮球后，所有核心功能仍有普通入口。
- [ ] Y900 使用适配大屏的布局，而非简单拉伸。

### 16.3 计划外饮食与勋章

- [ ] 计划外饮食可正常记录，且不会自动清零长期成果。
- [ ] 记录日、坚持日和均衡日分别计算。
- [ ] 累计勋章不因中断而熄灭。
- [ ] 连续记录与历史最长连续记录分别显示。
- [ ] 休息日不增加坚持日，也不打断连续记录。
- [ ] 勋章可由真实记录、补录和 NDM 导入记录触发。
- [ ] 普通勋章点亮不强制全屏、不阻断操作。
- [ ] 重要里程碑可提供不制造负担的可选奖励。

### 16.4 健康与数据

- [ ] 可根据已填写疾病情况提供饮食辅助，并显示必要边界提示。
- [ ] 健康数据支持手动录入和 NDM 文件导入。
- [ ] vivo 健康未接入时，不影响其他功能。
- [ ] 数据在关机和重启后仍可读取。
- [ ] 可导出 `.ndm.md` 数据文档和完整备份包。
- [ ] 导入时可预览、校验、去重和处理冲突。
- [ ] 导入失败不会破坏原数据。
- [ ] 断网时仍可查看本地记录并使用基础功能。

## 18. 实施前验证事项

以下属于后续设计或开发前的验证事项，不是新的产品需求问题：

1. vivo S7 和 Y900 的实际系统版本、Android API 等级及权限差异。
2. vivo Health Kit 的家庭自用接入资格、审核要求和实际可读数据类型。
3. 内置 AI 服务的识别能力、费用、隐私条款、稳定性和断网降级策略。
4. 食材营养数据库的单位、生熟重换算及数据质量。
5. 疾病饮食内容应依据可靠指南，并在实际使用前由具备资质的专业人员复核。
6. 固定参照物、不同餐具和常见食材的照片估算误差测试。
7. 角色立绘、悬浮头像和勋章的风格一致性及使用授权。
8. NDM 格式版本兼容、重复记录、冲突合并和异常恢复测试。
9. 悬浮球在两种设备上的遮挡、手势冲突、键盘避让和可访问性测试。
10. 勋章规则的配置化、边界条件和历史数据重算测试。
