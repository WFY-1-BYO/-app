# 营养师数据 Markdown（NDM）格式规范

> 格式暂名：Nutritionist Data Markdown，简称 NDM  
> 规范版本：1.0  
> 用途：家庭自用营养师 App 的数据导出、导入、迁移与备份  
> 文件后缀：`.ndm.md`

## 1. 格式定位

NDM 是一种**使用标准 Markdown 编写、但具有本软件固定结构和校验规则的专用数据文档**。

它不是普通笔记，也不是把数据库随便转换成几段文字，而是同时满足：

- 用户可以直接用 Markdown 阅读器查看。
- 用户可以在遵守规则时手动修改。
- App 可以稳定识别记录类型、字段、单位和关联关系。
- 两台设备可以根据唯一编号去重和合并。
- 后续版本可以通过格式版本号进行兼容升级。

建议文件名：

`营养师数据_2026-11-12_vivo-S7.ndm.md`

文件仍以 `.md` 结尾，因此保持通用可读性；中间的 `.ndm` 用于表明它是本软件的数据文档。

## 2. 设计原则

1. **可读**：不打开 App，也能看懂主要内容。
2. **可解析**：固定文档头、章节、记录标记和字段名称。
3. **可校验**：导入时检查版本、必填项、单位、编号和附件。
4. **可合并**：每条记录具有全局唯一编号及设备来源。
5. **可扩展**：新增字段不应破坏旧版本已有数据。
6. **本地优先**：文档和照片均由用户自行保管，不依赖云服务。
7. **不存敏感凭据**：不得写入 AI 密钥、账号密码或其他安全凭据。

## 3. 文档组成

### 3.1 文档头

文档必须使用 YAML Front Matter 开头：

```yaml
---
format: "nutritionist-data-markdown"
format_version: "1.0"
document_id: "export_20261112_094128_vivos7"
app_version: "1.0.0"
created_at: "2026-11-12T09:41:28+08:00"
timezone: "Asia/Shanghai"
source_device: "vivo-S7"
profile_id: "profile_local_001"
---
```

| 字段 | 必填 | 含义 |
| --- | --- | --- |
| format | 是 | 固定格式标识，用于区别于普通 Markdown |
| format_version | 是 | NDM 格式版本，不等于 App 版本 |
| document_id | 是 | 本次导出的唯一编号 |
| app_version | 是 | 导出数据的 App 版本 |
| created_at | 是 | 导出时间，采用带时区的 ISO 8601 格式 |
| timezone | 是 | 数据默认时区 |
| source_device | 是 | 来源设备标识 |
| profile_id | 是 | 单用户档案编号 |

### 3.2 固定章节

正文按以下顺序组织：

1. 个人档案
2. 配餐记录
3. 用餐记录
4. 运动记录
5. 健康指标
6. 餐具校准
7. 知识与成就
8. 附件清单
9. 导入导出说明

没有数据的章节可以保留标题并写“暂无记录”，不应随意删除固定章节。

### 3.3 记录标记

每条记录使用 HTML 注释作为机器标记。注释在普通 Markdown 阅读模式下不会干扰阅读。

```markdown
<!-- @record type=meal_plan id=plan_20261112_breakfast_vivos7_001 -->
### 2026-11-12 早餐

- 记录编号：plan_20261112_breakfast_vivos7_001
- 创建时间：2026-11-12T07:30:00+08:00
- 修改时间：2026-11-12T07:32:00+08:00
- 来源设备：vivo-S7

<!-- @endrecord -->
```

规则：

- `type` 表示记录类型。
- `id` 必须稳定且唯一，导入后不得重新随机生成。
- 每条记录还应保存创建时间、修改时间和来源设备。
- 每条记录以 `@record` 开始，以 `@endrecord` 结束。
- 正文标题可以方便用户阅读，但程序判断以记录标记和字段为准。

## 4. 各章节的数据结构

### 4.1 个人档案

以字段列表保存：

- 昵称。
- 年龄或出生日期。
- 身高及单位。
- 当前体重及单位。
- 日常活动水平。
- 饮食目标。
- 食物过敏。
- 忌口。
- 口味偏好。
- 已填写疾病情况。
- 医生或临床营养师饮食限制。
- 创建时间、修改时间和来源设备。

### 4.2 配餐记录

每次配餐是一个独立记录块，内部包含：

#### 基本信息

- 配餐编号、日期和餐次。
- 个人目标快照。
- 运动背景。
- 配餐理由。
- 整体评价。
- 创建及修改时间、来源设备。

#### 菜品明细

| 菜品编号 | 菜名 | 份量 | 做法 |
| --- | --- | --- | --- |
| dish_001 | 示例菜名 | 1 份 | 简明步骤 |

#### 当次食材明细

| 食材编号 | 名称 | 来源 | 估算量 | 确认量 | 单位 | 生熟 | 用于配菜 | 照片 |
| --- | --- | --- | ---: | ---: | --- | --- | --- | --- |
| food_001 | 示例食材 | 当次已有 | 100 | 110 | g | 生重 | 是 | assets/images/food_001.jpg |
| food_002 | 推荐食材 | 额外推荐 | - | - | g | 生重 | 否 | - |

强制规则：

- 只有`当次已有`且`用于配菜=是`的食材，才能进入菜品和营养计算。
- `额外推荐`只能作为建议，禁止计入本次菜品和营养合计。
- 不存在库存数量、剩余数量或扣减数量字段。
- 估算值与用户确认值必须分开保存。

#### 营养估算

| 能量（kcal） | 碳水（g） | 蛋白质（g） | 脂肪（g） | 碳水供能比 | 蛋白质供能比 | 脂肪供能比 |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 0 | 0 | 0 | 0 | 0% | 0% | 0% |

实际导出时应填写真实估算结果，不得把模板中的零值当作有效测量值。

### 4.3 用餐记录

每条实际用餐记录包括：

- 用餐编号及其关联的配餐编号。
- 实际用餐时间和餐次。
- 菜品和实际食用量。
- 是否属于计划外饮食。
- 实际营养估算。
- 评价和备注。
- 创建及修改时间、来源设备。

计划外饮食只改变该次记录内容，不自动清零坚持统计。

### 4.4 运动记录

| 字段 | 说明 |
| --- | --- |
| 运动编号 | 唯一编号 |
| 状态 | 计划、已完成、已取消或部分完成 |
| 项目 | 跑步、步行等 |
| 开始时间 | 带时区时间 |
| 时长 | 统一使用分钟 |
| 强度 | 使用固定枚举及说明 |
| 数据来源 | 手动、导入或 vivo |
| 关联配餐 | 可为空，填写配餐编号 |

计划运动不得被当作已经完成的运动。

### 4.5 健康指标

采用长表结构，每一行是一项测量：

| 指标编号 | 类型 | 数值 | 单位 | 测量时间 | 来源 | 参考范围 | 备注 |
| --- | --- | ---: | --- | --- | --- | --- | --- |
| metric_001 | 示例指标 | 0 | 示例单位 | 2026-11-12T08:00:00+08:00 | 手动 | - | 模板示例 |

血压等成对指标应在同一记录中保存收缩压和舒张压，不能为了套用单值表而丢失关联。实际模板可为此类指标使用独立记录块。

### 4.6 餐具校准

- 餐具编号和名称。
- 类型，如碗、勺或杯。
- 容量及单位。
- 校准方法。
- 参照物说明。
- 校准日期。
- 误差或适用范围说明。
- 关联照片。

水的容量校准不得自动等同于盐、油、米等食材的重量校准。

### 4.7 知识与成就

- 已读知识编号、标题和阅读时间。
- 收藏状态。
- 勋章编号、名称和点亮时间。
- 奖励内容、状态和领取时间。
- 坚持统计快照。

坚持统计快照仅用于阅读，原始用餐、运动和成就记录才是重新计算统计结果的依据。

### 4.8 附件清单

| 附件编号 | 相对路径 | 类型 | 关联记录 | 校验值 |
| --- | --- | --- | --- | --- |
| attachment_001 | assets/images/food_001.jpg | image/jpeg | food_001 | 导出时生成 |

规则：

- 只使用相对路径，不保存某台设备的绝对路径。
- 单个 `.ndm.md` 文件可以不包含照片，但必须标注缺失附件。
- 完整备份时，文档与 `assets` 文件夹共同保存。
- 不使用 Base64 把大量照片塞进 Markdown，以免文档难以阅读和编辑。

## 5. 字段书写规则

### 5.1 时间与单位

- 时间统一采用 ISO 8601，并包含时区。
- 重量默认使用 `g`，容量默认使用 `ml`。
- 能量默认使用 `kcal`，运动时长默认使用 `min`。
- 健康指标必须保留原始单位，不在没有说明的情况下擅自换算。
- 生重、熟重和可食部必须明确区分。

### 5.2 空值与长文本

- 未知或不适用的值使用 `-`，不随意填写零。
- 表格单元格中的换行使用 `<br>`。
- 单元格中的竖线必须转义为 `\|`。
- 很长的做法、医生限制或备注优先使用记录块中的列表，不强行塞入宽表格。

### 5.3 枚举值

格式规范需要固定常见枚举，例如：

- 餐次：早餐、午餐、晚餐、加餐。
- 食材来源：当次已有、额外推荐。
- 生熟状态：生重、熟重。
- 运动状态：计划、已完成、已取消、部分完成。
- 数据来源：手动、导入、vivo。

程序导入时应检查枚举，不把任意自然语言直接当作合法状态。

## 6. 导入规则

1. 检查 `format` 是否为 `nutritionist-data-markdown`。
2. 检查 `format_version` 是否受支持。
3. 校验文档头、固定章节、记录标记和必填字段。
4. 校验编号唯一性、时间、数值、单位和枚举。
5. 校验当次食材与额外推荐的使用关系。
6. 校验附件路径及文件是否存在。
7. 展示新增、重复、冲突、错误和缺失附件数量。
8. 完全重复的记录默认跳过。
9. 同一编号但内容不同的记录进入冲突清单，由用户决定。
10. 导入失败时不得破坏原数据；正式写入前先创建本地备份。

对于较新版本产生的未知字段，可以提示“部分内容未识别”，不得静默丢弃后声称完整导入。

## 7. 导出形式

### 7.1 轻量数据文档

只导出一个 `.ndm.md` 文件：

- 包含文字数据。
- 照片以相对链接和缺失状态表示。
- 适合快速查看、文字修改和小范围迁移。

### 7.2 完整备份包

建议目录结构：

```text
营养师数据_2026-11-12/
├── data.ndm.md
└── assets/
    └── images/
        └── food_001.jpg
```

完整备份包可以压缩传输，但解压后必须保留上述相对路径。

## 8. 与普通 Markdown 的区别

| 能力 | 普通 Markdown | NDM |
| --- | --- | --- |
| 自由书写 | 是 | 仅说明区域允许自由书写 |
| 固定格式标识 | 无 | 有 |
| 固定数据章节 | 无 | 有 |
| 唯一记录编号 | 无 | 有 |
| 字段及单位校验 | 无 | 有 |
| 双设备去重合并 | 无 | 有 |
| 食材来源约束 | 无 | 有 |
| 照片关联和校验 | 无 | 有 |
| 版本兼容处理 | 无 | 有 |

因此，App 不需要承诺导入任意 Markdown 笔记，只保证导入符合本规范的 `.ndm.md` 文件。

## 10. 当前版本边界

- 本规范定义数据交换格式，不规定 App 内部必须使用 Markdown 代替本地数据库。
- 日常运行仍以本地数据库保证查询、统计和写入效率。
- NDM 是可读、可迁移的外部数据格式。
- 第二版增加云服务时，仍可沿用该格式进行用户自主备份。
