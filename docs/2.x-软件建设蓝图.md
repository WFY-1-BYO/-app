## 七、工程与质量体系【已定】执行细则

- **分层**：`pages`（页面）/ `lib`（纯逻辑）/ `store`（Zustand）/ `types` / `tests`；新功能优先落在 `lib` 并配套单测。
- **四门禁**：typecheck → lint → test（全量）→ build；全部通过才允许打版本标签。
- **发布**：`v*` 标签 → CI 双 job（Web zip / 安卓 APK）→ GitHub Release 附两者 → 下载后**直接放进对话**。
- **版本号**：`x.y.z`，功能更新 `y+1`、缺陷修复 `z+1`；`versionCode` 与 `package.json`、`build.gradle` 三处同步。
- **安卓构建固定条件（本次教训）**：JDK **21**、`ANDROID_HOME` 与 `ANDROID_SDK_ROOT` 必须同路径、compileSdk 35 / build-tools 35.0.0。1.5 失败于 SDK 双路径，1.6 失败于 JDK 17，均属此类。
- **凭据检查**：提交前密钥字符串零命中；Release 产物不含任何密钥。
- **每个功能的完成定义（DoD）**：单测通过 + 全量测试通过 + 类型 / Lint 通过 + 构建通过 + git 提交 + 安装包进对话 + Release 同步。七项缺一不算完成。

## 八、风险与边界（如实列）

- **纯前端方案的密钥理论上仍可从设备提取**（V1.4 总账已如实写明），别在共用设备上填重要密钥。
- **联网识别与「数据只存本机」的边界**：仅照片在主动识别时离机，饮食记录仍留本机；这条边界要不要写进设置页说明，待你确认。
- **成本**：DeepSeek 余额约 5 元，拍照识别与每日知识是持续调用，量大需充值。
- **识别精度天花板**：叠放食材、深色酱汁里的肉、切碎混合的配菜，仍会标「需你确认」而不是硬猜（V1.4 总账原话）。
- **CI 对环境版本敏感**：1.5 / 1.6 两次 APK 失败都不是代码问题，是构建环境；已列为 2.0 必须先清零项。
